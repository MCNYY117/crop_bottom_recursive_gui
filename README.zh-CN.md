# 📸 批量裁剪图片底部工具

一个带图形界面的 Python 工具，用于批量裁剪图片底部区域，支持递归处理子目录并保持原有目录结构。

## ✨ 功能特性

| 功能 | 说明 |
|------|------|
| 🖥️ **图形界面** | 基于 tkinter，无需命令行，简单易用 |
| 📁 **递归子目录** | 自动遍历输入目录下的所有子文件夹 |
| 🔄 **保持目录结构** | 输出时重建相同的相对路径 |
| 💾 **覆盖或另存** | 可选择输出到新目录或直接覆盖原图（有二次确认） |
| 🖼️ **多格式支持** | 默认支持 JPG、JPEG、PNG、BMP、TIFF |
| 🛡️ **先检查再动刀** | 开工前把每张图的高度都读一遍；只要有一张矮于 Y 就整批拒绝，一个文件都不写 |
| 🎨 **尽量保住 JPEG 画质** | 把原图自己的量化表和 EXIF 一起搬过去，重存的开销远小于默认重编码 |
| 📊 **实时日志** | 显示处理进度和结果，成功与失败分别计数 |
| ⚡ **非阻塞界面** | 后台线程处理，界面不卡顿 |

## 🎯 适用场景

- 批量去除图片底部的日期时间戳
- 删除图片下方的水印或版权信息
- 裁剪掉图片底部的多余空白区域
- 统一大量图片到相同高度

## 📥 安装与使用

需要 **Python 3.8 或更高版本**，以及 [Pillow](https://python-pillow.org/)。

### 方式一：直接运行 Python 脚本

#### 1. 安装依赖

```bash
pip install -r requirements.txt
```

（也可以直接 `pip install Pillow`）

#### 2. 获取代码

```bash
git clone https://github.com/MCNYY117/crop_bottom_recursive_gui.git
cd crop_bottom_recursive_gui
```

#### 3. 运行程序

```bash
python crop_bottom_recursive_gui.py
```

### 方式二：使用打包好的可执行文件

如果 Releases 页面提供了打包版本，下载后双击运行即可，无需安装 Python。
没有的话可以用下面的 [PyInstaller 打包](#-打包为独立可执行文件) 自己生成一个。

## 🖥️ 界面操作说明

### 界面字段说明

| 字段                | 说明                                                      |
| ------------------- | --------------------------------------------------------- |
| **输入根目录**      | 存放图片的最顶层文件夹（程序会递归遍历所有子目录）        |
| **输出根目录**      | 输出文件夹，留空则覆盖原文件（有二次确认警告）            |
| **裁剪起始 Y 坐标** | 保留图片顶部 0 到 (Y-1) 行，从第 Y 行开始往下的部分被裁掉 |
| **文件扩展名**      | 空格分隔，默认支持 `.jpg .jpeg .png .bmp .tiff`           |

### 操作步骤

1. 点击 **"输入根目录"** 旁边的 **"浏览"** 按钮，选择包含图片的文件夹
2. 点击 **"输出根目录"** 旁边的 **"浏览"** 按钮，选择输出文件夹（可选）
3. 输入 **"裁剪起始 Y 坐标"**（例如输入 `1000`）
4. 确认 **"文件扩展名"** 列表是否正确
5. 点击 **"开始裁剪"** 按钮
6. 观察下方日志区域查看处理进度

## 📐 裁剪原理

- 坐标原点在图片**左上角 (0,0)**，Y 轴向下增加
- 输入 `Y` 值后，程序裁剪图片的 `[0, 0]` 到 `[宽度, Y]` 区域
- 例如：原图尺寸 1920×1080
  - 输入 `Y = 1000` → 保留顶部 0~999 行（1000 像素），底部 80 像素被裁掉
  - 输入 `Y = 500` → 保留顶部 0~499 行（500 像素），底部 580 像素被裁掉

### ✅ 开工前会检查什么

**每张图的高度，不是只看第一张。** 程序会先把所有找到的文件头读一遍，只要有**任何一张**
矮于 Y，就停下来并把其中最多十个列在日志里 —— 此时**一个文件都还没有写**。

这一步之所以必要，是因为 Pillow 裁到底部之外时**不会报错**，而是静默地在下方**补边**
（JPEG 补黑边，PNG 可能是透明边）。一个装满补边图的半成品输出目录，比直接拒绝糟糕得多。

### 💾 保存时会做什么

裁剪本身**不重采样** —— 留下来的就是你原来的像素，不会像缩放那样糊掉。但**写文件**是另一回事：

- **JPEG 沿用原图自己的量化表**，用源文件本来就有的压缩方式重存，而不是 Pillow 的默认值；
  EXIF 也一并带过去，拍摄时间、GPS、相机型号、方向都能保住。
- **PNG / BMP / TIFF** 是无损的，像素原样保留。
- 某个格式或某个文件吃不下这套参数时，退回普通保存，而不是让这个文件失败。

**JPEG 依然是重新编码的，只是温柔得多。** 以同一张源图的无损裁剪为基准实测：
透传量化表一次处理后，每通道平均绝对误差 **4.2**，默认重编码是 **7.9**，
而且输出文件大约大 63% —— 也就是说它保住了默认重编码扔掉的那些细节。

但这个优势**不等于幂等**：每多跑一遍，像素还会再偏移一点（约 **+1.6 / 遍**）。
所以**尽量不要对已经处理过的输出再跑一次**。

> 💡 **原图请先备份。** 第一次使用建议先输出到一个单独的目录看看效果。

## 🔧 打包为独立可执行文件

如果需要分享给没有 Python 环境的用户，可以使用 PyInstaller 打包：

### 1. 安装 PyInstaller

```bash
pip install pyinstaller
```

### 2. 执行打包命令

```bash
pyinstaller -F -w crop_bottom_recursive_gui.py
```

### 3. 获取可执行文件

打包完成后，在 `dist` 文件夹中找到 `crop_bottom_recursive_gui.exe`，可直接双击运行。

### 打包参数说明

| 参数          | 说明                           |
| ------------- | ------------------------------ |
| `-F`          | 打包成单个可执行文件           |
| `-w`          | 隐藏命令行窗口（GUI 程序专用） |
| `-i icon.ico` | （可选）添加程序图标           |

### 高级打包选项

#### 使用虚拟环境减小体积

```bash
# 创建虚拟环境
python -m venv venv
# 激活虚拟环境（Windows）
venv\Scripts\activate
# 激活虚拟环境（Mac/Linux）
source venv/bin/activate

# 仅安装必要依赖
pip install Pillow pyinstaller

# 打包
pyinstaller -F -w crop_bottom_recursive_gui.py
```

#### 添加程序图标

```bash
pyinstaller -F -w -i my_icon.ico crop_bottom_recursive_gui.py
```

## ❓ 常见问题

### Q1: 为什么某些图片没有被处理？

**A:** 请检查文件扩展名是否在支持列表中：
- 默认支持：`.jpg`、`.jpeg`、`.png`、`.bmp`、`.tiff`
- 如需处理其他格式，在界面中修改 **"文件扩展名"** 字段

### Q2: 处理大图片时界面会卡顿吗？

**A:** 不会。程序使用子线程处理，界面保持响应。如果处理大量图片，请耐心等待日志更新。

### Q3: 裁剪后图片质量会下降吗？

**A:** 会比普通保存好，但不是无损。

- **裁剪本身不重采样**，留下来的就是原像素，不会像缩放那样糊掉。
- **JPEG** 依然是重新编码（有损），只是改成沿用**原图自己的量化表**，
  比 Pillow 默认质量好得多，**EXIF 也会保留**。
- **PNG / BMP / TIFF** 是无损格式，画质不受影响。

具体数字和「不要反复处理同一批文件」的原因，见上面的 [保存时会做什么](#-保存时会做什么)。
**原图请先备份**，想验证效果就先拿几张图输出到另一个目录看看。

### Q4: 为什么程序报错 "裁剪 Y 坐标超出图片高度"？

**A:** 您输入的 Y 值大于这批图里**至少一张**的高度。日志会列出是哪些图、各自多高。
程序在开始处理前就把所有图片都检查过了，**此时还没有写过任何文件**。
把 Y 调到不大于最矮那张的高度，然后重试即可。

### Q5: 覆盖原文件时如何避免数据丢失？

**A:** 建议：
1. 先使用**输出目录**模式测试几张图片
2. 确认效果满意后再批量处理
3. 重要数据请先备份（覆盖模式下没有撤销）

### Q6: 可以只裁剪图片右侧吗？

**A:** 当前版本仅支持底部裁剪。如需其他方向，可以修改代码中的 `crop()` 参数：
- 裁剪右侧：`img.crop((0, 0, crop_x, img.height))`
- 裁剪顶部：`img.crop((0, crop_y, img.width, img.height))`
- 裁剪左侧：`img.crop((crop_x, 0, img.width, img.height))`

### Q7: 所有图片尺寸必须一致吗？

**A:** 是的。如果图片尺寸不同，同一个 Y 坐标会导致不同的裁剪效果。如需处理不同尺寸的图片，建议先统一尺寸。
